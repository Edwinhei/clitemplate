## 已确立的工程约束(不要破坏)

| 约束 | 落在哪 | 防什么 |
|---|---|---|
| **契约优先** —— 先改契约再改实现;删掉 `apps/api` 前端要能编译 | `contracts/README.md` | 前端依赖实现而非契约 |
| **只用可擦除语法** —— `erasableSyntaxOnly: true` | `tsconfig.base.json` | 被迫加构建步骤 |
| **`types` 按包声明** —— base 不写 `types` | 各包 tsconfig | 同构包偷偷绑死 Node |
| **按能力域分目录** —— `packages/<域>/<包>/` | 目录结构 | 改一个需求跳三个目录 |
| **配置属于 app** —— `cordis.yml` 在 `apps/cli/`,从包内路径解析 | `apps/cli/` | 仓库根目录暗示"只有一个应用" |
| **包名即分层** | 命名规范(见下) | 可替换性看不见 |

### 包名规范

```
@ctl/cli                产品装配（apps/）
@ctl/<能力>             契约    ← 稳定，动它=动协议
@ctl/<能力>-<实现>      提供方  ← 随便换
@ctl/<能力>-<x>-policy  策略    ← 随便摘
@ctl/tool-<能力>        消费方  ← 不挂就没有
```

> 换项目时全局替换 `@ctl` 这个 scope 即可。

### API 选型的关键结论

- **NestJS**:装饰器 + 参数属性 + 元数据 → **开发期必须构建**,且不能纯 ESM
  (Node 22 的 `require(esm)` 缓解了"用不了 ESM 库"的痛,但依赖链上有顶层 await 仍然不行)

- **如果选 NestJS**:把它隔离成"例外",在 `apps/api/tsconfig.json` 里显式
  `erasableSyntaxOnly: false` + 注释说明为什么

## 已踩的坑(都记在根 README 的「已知陷阱」)

1. **`cordis.yml` 顶层必须是数组** —— 全部注释掉 = `null`,报
   `TypeError: config file must be a top-level array`;要空就写 `[]`
2. **条目 `id` 必须唯一** —— `duplicate loader entry id: xxx`
3. **读 Cordis 错误三步** —— 看动词(`import`/`apply`)→ 看括号里的 `id` → 看最底下 `[cause]`
4. **`--import tsx` 依赖 cwd** —— 仓库外调用会 `Cannot find package 'tsx'`;裸 node 无此问题
5. **`@types/node` 要显式装** —— tsconfig 写了 `types: ["node"]` 但没装包,
   报错离根因有两跳(「找不到 process」→ 其实是「@types/node 没装」)
6. **叶子包要声明自己的依赖** —— pnpm 严格 node_modules 不提升

## 当前进度详情:步骤 3(进行中)

### 目标

建第一条完整能力 seam,并验证 **「换实现,消费方零改动」**。

### 要建的包

```
packages/notify/
├── notify/          @ctl/notify           ① 契约（只有类型，零实现，无 types:node）
├── notify-console/  @ctl/notify-console   ② 提供方 A：打控制台
├── notify-file/     @ctl/notify-file      ② 提供方 B：写文件（需 types:node）
└── tool-notify/     @ctl/tool-notify      ③ 消费方（inject: ['notify']）
```

### 关键设计点

- **契约包只有 `interface` + `declare module`,没有 `apply`** —— 它不是插件
- **消费方用 `import type {} from '@ctl/notify'`** —— 只引声明合并,运行时擦除
- **`apps/cli/package.json` 要依赖提供方和消费方** —— 因为 `cordis.yml` 用包名引用
- **契约包和消费方不写 `types: ["node"]`** —— 保持同构;只有 `notify-file` 要写(它用 `node:fs`)

### 验收实验

1. `pnpm ctl` → 看到 `📣 [ops] CLI 启动完成`
2. 把 `cordis.yml` 里 `name: '@ctl/notify-console'` 改成 `'@ctl/notify-file'`
   (并同步改 `apps/cli/package.json` 的依赖)→ 变成写文件
   **而 `tool-notify` 和 `notify` 两个包一个字不改**
3. 在 `tool-notify` 里临时写 `process.cwd()` → TS 应报「找不到名称 process」
